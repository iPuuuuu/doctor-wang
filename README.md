## 当前可运行 Demo 使用说明

### 1. APK 输出路径
Android debug APK 构建完成后，默认输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

在当前仓库绝对路径下对应为：

```text
C:\Users\wmh\Desktop\doctor-wang\app\build\outputs\apk\debug\app-debug.apk
```

### 2. Debug 安装到手机
1. 先执行 debug 构建：

```bat
.\gradlew.bat assembleDebug
```

2. 构建完成后，把 `app-debug.apk` 发到手机，或用数据线执行：

```bat
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

3. 如果手机首次安装 APK 被系统拦截，请允许“安装未知来源应用”。

### 3. 当前 Android 环境策略
- `debug` 包默认连接：`http://10.0.2.2:8080/`
- `release` 包默认连接：构建时注入的线上 HTTPS 地址
- 如果没有注入 `doctorWangReleaseBaseUrl` / `DOCTOR_WANG_RELEASE_BASE_URL`，release 会落到占位域名：

```text
https://doctor-wang-demo.example.com/
```

这意味着：
- 开发调试阶段继续使用本地后端服务最方便
- 真正给用户安装使用前，应先把后端部署上线，再构建 release 包

### 4. 本地后端启动方式
后端目录：

```text
doctor-wang-mock-server
```

启动命令：

```bat
cd doctor-wang-mock-server
.\gradlew.bat bootRun
```

或者直接双击：

```bat
doctor-wang-mock-server\start-mock-server.bat
```

默认本机访问地址：

```text
http://127.0.0.1:8080/
```

### 5. 本地真机联调步骤
1. 电脑和手机连接同一个 Wi‑Fi。
2. 启动 `doctor-wang-mock-server` 后端服务。
3. 在电脑命令行执行：

```bat
ipconfig
```

4. 找到当前网络对应的 IPv4 地址，例如 `192.168.1.10`。
5. 打开手机上的 Doctor-Wang。
6. 进入“服务设置”，把地址改成：

```text
http://<你的电脑局域网IP>:8080/
```

例如：

```text
http://192.168.1.10:8080/
```

7. 点击“保存服务地址”。
8. 点击“测试连接”。

### 6. 上线部署后的推荐发布方式
推荐顺序：
1. 先把 `doctor-wang-mock-server` 后端部署到公网可访问的 HTTPS 域名。
2. 构建 Android release 时注入线上地址：

```bat
.\gradlew.bat assembleRelease -PdoctorWangReleaseBaseUrl=https://your-domain.example/
```

也可以用环境变量：

```bat
set DOCTOR_WANG_RELEASE_BASE_URL=https://your-domain.example/
.\gradlew.bat assembleRelease
```

3. release 包构建完成后，APK 默认就会连接你配置的线上后端，普通用户安装后无需再手动填写局域网地址。

### 7. 模拟器 / 真机 / 线上地址说明
- Android 模拟器默认可用：`http://10.0.2.2:8080/`
- Android 真机不能使用 `10.0.2.2`
- 真机本地调试必须改成你电脑的局域网 IP，例如：`http://192.168.1.10:8080/`
- 真正发布给用户时，推荐使用线上 HTTPS 地址，而不是局域网地址

## 1. 项目概述

### 1.1 产品愿景
Doctor-Wang 是一款面向个人用户的 AI 健康助手 Android 应用，核心价值是帮助用户完成日常健康咨询、体检/检查报告上传与解析、健康档案管理，以及就医前后的辅助决策。

### 1.2 产品目标
第一版产品（MVP）需要完成以下闭环：

1. 用户注册/登录
2. 进入首页并查看个人入口
3. 发起 AI 问诊对话
4. 上传医疗资料（图片/PDF）
5. 查看 AI 报告解析结果
6. 浏览个人健康档案
7. 管理账号与设置

### 1.3 用户定位
目标用户包括：

- 有日常健康咨询需求的普通个人用户
- 有体检报告、影像报告、化验单解读需求的用户
- 希望持续沉淀个人健康档案的用户
- 希望在就医前获得辅助整理、问诊建议的用户

### 1.4 MVP 成功标准
在 Android 真机上完成以下体验：

- 打开 App
- 完成登录
- 进入健康主页
- 点击 AI 问诊
- 像 ChatGPT 一样完成对话
- 上传一份医疗报告
- 查看 AI 解析结果

达到以上标准即可认为第一版 Demo 可展示、可验证方向。

## 18. 风险清单与应对策略

### 风险 1：需求过多导致第一版失控
**应对：** 严格聚焦 MVP，只先做登录、首页、聊天、上传、报告详情、档案、设置。

### 风险 2：后端接口定义频繁变化
**应对：** 先输出接口文档草案，前后端评审后再开发。

### 风险 3：聊天体验不像 ChatGPT
**应对：** 第一版先保证对话闭环，第二版再优化流式体验、动画和会话管理。

### 风险 4：文件上传兼容问题
**应对：** 第一版只支持 PDF/JPG/PNG，使用官方文件选择方案。

### 风险 5：医疗内容误导风险
**应对：** 明确免责声明，高风险内容提示线下就医。
