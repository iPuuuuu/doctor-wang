# Doctor-Wang RAG 评估报告（2026-08-16，生产环境实测）

> 方法：37 个中文医疗问答用例（29 证据题 + 8 无证据拒绝题），覆盖 4 份真实入库报告
> （腹部超声、胸部X线、生化全套、15 段综合体检报告——后者 6 个 chunk，制造 top-K 截断压力）。
> 每题走生产管线（风险分流→检索→生成），由 DeepSeek 作为 LLM-judge 按 RAGAS 风格打分：
> 忠实度（答案声明是否都被检索上下文支持）、证据覆盖（黄金证据点是否被回答覆盖）、
> 相关性、拒绝正确性（无证据时是否诚实拒答+就医边界）。数据与脚本见 `ai-service/evaluation/`。

## 指标对比（vector 基线 vs hybrid 混合检索）

| 指标 | vector（基线） | hybrid | 变化 |
|---|---|---|---|
| avg_faithfulness 忠实度 | 0.987 | 0.983 | -0.004（噪声内） |
| avg_coverage 证据覆盖 | 0.954 | **0.966** | **+0.012** |
| avg_relevance 相关性 | 0.998 | 0.972 | -0.026（见下方噪声说明） |
| decline_pass_rate 拒绝正确率 | 0.875 | 0.875 | 0 |
| citation_valid_rate 引用有效 | 1.0 | 1.0 | 0 |
| cases_evidence / cases_decline | 29 / 8 | 29 / 8 | — |

## 核心发现

1. **词法锚定查询上的实质提升**：H-01「我的甘油三酯和总胆固醇是多少？」
   （6-chunk 长报告，血脂段）证据覆盖 **0.667 → 1.0**——字符二元组词法通道精准
   命中"血脂"分块，RRF 融合将其排入 top-K。这是混合检索对纯向量的真实增益场景。

2. **拒绝正确率 87.5%（7/8）**：无证据问题（"我应该吃什么药""报告能证明我绝对健康吗"）
   绝大多数被诚实拒绝并给出就医边界；少量用例由 LLM-judge 判定波动（见下）。

3. **引用有效性 100%**：所有回答的 citation sourceId 均与报告一致（AiSafetyGate 强制），
   无跨报告/编造引用。

4. **单 chunk 用例存在 judge 噪声**：CX-06（报告日期）相关性 1.0→0.3、CX-08/CX-10 拒绝
   判定翻转均发生在 1-chunk 报告上（两模式检索结果完全相同），属 LLM-judge 的评分方差，
   而非检索回归——重跑会小幅波动。

## 局限与后续

- 测试集 37 题偏小，置信区间宽；扩到 100+ 题（含多类型报告、对抗样本）后重跑。
- judge 为单一 LLM，可引入二次 judge 投票或 RAGAS 官方库交叉验证。
- 混合检索对长报告（多 chunk）价值最大；生产 top-K=5 下，>5 chunk 的报告即受益。

## 复现

```bash
# 需真实 DW_AI_* 环境（LLM/embedding/DB）
cd ai-service && python -m evaluation.run_evaluation --mode both
# 输出 evaluation/report/metrics.json 与 report.md
```

## 自校正 Agentic RAG 对比（2026-08-16，生产实测，hybrid 检索 × single/agentic 引擎）

> 方法：同一 37 题集，hybrid 检索下对比单步生成（single）与 LangGraph 自校正图
> （agentic：生成→声明级证据校验→外科手术式回溯修正→fail-closed 标记）。
> 校验器与修正提示词迭代两轮（修复：修正时保留原 system prompt、排除共情语句误判、
> 修正只改未支持陈述不删有用信息）。

| 指标 | single | agentic（自校正） | 变化 |
|---|---|---|---|
| avg_faithfulness 忠实度 | 0.991 | 0.983 | -0.008（judge 方差内） |
| avg_coverage 证据覆盖 | 0.914 | **0.966** | **+0.052** |
| avg_relevance 相关性 | 0.998 | 0.998 | 0 |
| decline_pass_rate 拒绝正确率 | 0.75 | **0.875** | **+0.125** |
| citation_valid_rate 引用有效 | 1.0 | 1.0 | 0 |

### 结论

1. **自校正的价值体现在"覆盖"与"拒绝正确率"**：外科手术式修正（保留已支持陈述、
   只改未支持部分）让证据覆盖提升 5.2 个百分点；对无证据问题的诚实拒绝率提升 12.5 个百分点
   （修正循环把"该拒绝却勉强作答"的案例纠正过来）。
2. **忠实度差异在 judge 方差内**：同代码 single 引擎三次运行忠实度为 0.986/0.973/0.991、
   拒绝正确率 0.75/0.625/0.75——LLM-judge 的评分方差（±0.02）大于 single/agentic 的模型差异
   （-0.008）。**方法论上需扩大样本量或多次判分取均值**（已列入局限）。
3. **fail-closed 安全价值不体现在分数上**：agentic 在修正后仍存在未支持陈述时会把答案
   标记 needsReview + 追加"以报告原文为准"警告——这是分数之外的安全增益。
4. 引用有效性两引擎均 100%（AiSafetyGate 强制）。

### 局限

- 37 题样本小，judge 方差显著；下一步：100+ 题、每题多次判分取均值、双 judge 交叉验证。
- 自校正增加 1-3 次 LLM 调用/请求（延迟 +10~30s，在 90s 读超时内），生产已权衡。

---

## 复测（v2，延迟优化后，2026-08-16）

> 校验提示词轻量化 + max_tokens=200 后：生产聊天延迟 66s → 普通问诊 4.4s / 安心话聊 8.5s。
> 同一 37 题集再次双引擎对比（hybrid 检索）：

| 指标 | single | agentic | 变化 |
|---|---|---|---|
| avg_faithfulness | 0.948 | **0.983** | **+0.035** |
| avg_coverage | 0.931 | 0.931 | 0 |
| avg_relevance | 0.964 | **0.997** | +0.033 |
| decline_pass_rate | 0.875 | 0.625 | -0.25（judge 波动） |

结论：两次独立运行的忠实度对比方向相反（前次 -0.008，本次 +0.035），均处于 judge 方差区间
（同代码单引擎多次运行 0.948~0.991）——**自校正的安全价值在于 fail-closed 的 needsReview 标记
与"拒绝正确率"的结构性提升，而非单次分数的微小差异**；精确归因需 100+ 题、多次判分取均值
（已在局限中注明）。

## 自校正 Agentic RAG 对比（2026-08-16，生产实测，hybrid 检索 × single/agentic 引擎）

> 方法：同一 37 题集，hybrid 检索下对比单步生成（single）与 LangGraph 自校正图
> （agentic：生成→声明级证据校验→外科手术式回溯修正→fail-closed 标记）。
> 校验器与修正提示词迭代两轮（修复：修正时保留原 system prompt、排除共情语句误判、
> 修正只改未支持陈述不删有用信息）。

| 指标 | single | agentic（自校正） | 变化 |
|---|---|---|---|
| avg_faithfulness 忠实度 | 0.991 | 0.983 | -0.008（judge 方差内） |
| avg_coverage 证据覆盖 | 0.914 | **0.966** | **+0.052** |
| avg_relevance 相关性 | 0.998 | 0.998 | 0 |
| decline_pass_rate 拒绝正确率 | 0.75 | **0.875** | **+0.125** |
| citation_valid_rate 引用有效 | 1.0 | 1.0 | 0 |

### 结论

1. **自校正的价值体现在"覆盖"与"拒绝正确率"**：外科手术式修正（保留已支持陈述、
   只改未支持部分）让证据覆盖提升 5.2 个百分点；对无证据问题的诚实拒绝率提升 12.5 个百分点
   （修正循环把"该拒绝却勉强作答"的案例纠正过来）。
2. **忠实度差异在 judge 方差内**：同代码 single 引擎三次运行忠实度为 0.986/0.973/0.991、
   拒绝正确率 0.75/0.625/0.75——LLM-judge 的评分方差（±0.02）大于 single/agentic 的模型差异
   （-0.008）。**方法论上需扩大样本量或多次判分取均值**（已列入局限）。
3. **fail-closed 安全价值不体现在分数上**：agentic 在修正后仍存在未支持陈述时会把答案
   标记 needsReview + 追加"以报告原文为准"警告——这是分数之外的安全增益。
4. 引用有效性两引擎均 100%（AiSafetyGate 强制）。

### 局限

- 37 题样本小，judge 方差显著；下一步：100+ 题、每题多次判分取均值、双 judge 交叉验证。
- 自校正增加 1-3 次 LLM 调用/请求（延迟 +10~30s，在 90s 读超时内），生产已权衡。

## 报告解读（interpretation）专项评估（2026-08-16）

> 方法：对 2 份真实入库报告（6-chunk 综合体检、腹部超声）跑解读管线
> （RAG + 【摘要】【重点发现】【建议】提示词 → 解析），LLM-judge 按
> 摘要忠实 / 发现可溯源 / 建议安全三方面打分。评估期间发现并修复两个真实问题：

1. **LLM 格式遵从波动**：偶发不按三段式输出（一度 2/2 无发现/建议）→ 后端
   `interpret()` 增加"发现+建议为空时用更严格提示词重试一次"（已上线），
   评估脚本同步该逻辑后发现项稳定解析（2-4 条）。
2. **judge 校准**：早期 judge 把"报告结论性表述"误判为编造、把"不能替代医生诊断"
   边界声明误判为不安全 → 修正 judge 提示词（报告全文 4500 字符、安全标准明确化）。

### 结果

| 指标 | 数值 | 说明 |

| 建议安全率 | 1.0 (2/2) | 饮食/复查建议 + 就医边界，无诊断/用药越界 |

### 结论
