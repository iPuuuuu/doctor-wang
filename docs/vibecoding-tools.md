# Vibecoding 工具清单（2026 实用版）

> 适合：想用 AI 辅助开发做网站、Web App、脚本、自动化工具、AI 产品的人  
> 目标：不是装最多工具，而是尽快搭出一套**能写、能跑、能改、能上线**的工作流

---

## 1. 先讲结论：你其实不需要一开始装很多

很多人一上来会觉得自己需要：

- 编辑器
- AI 编码工具
- 模型 API
- 数据库
- 部署平台
- 测试工具
- 设计工具
- 自动化工具
- 日志监控
- 协作工具

看起来全都要，但**真正起步时的必需品通常只有 4 类**：

1. **一个主力编辑器 / IDE**
2. **一个 AI 编码助手**
3. **一个运行环境**
4. **一个部署方式**

先把这 4 个打通，你就已经能开始 vibecoding 了。

---

## 2. 最小可行工具栈（推荐起步版）

如果你现在什么都没有，建议先用这套：

### 2.1 最小栈

- **编辑器**：VS Code 或 Cursor
- **AI 编码助手**：Claude Code / Cursor / GitHub Copilot 三选一
- **运行环境**：Node.js 或 Python ��选一
- **版本管理**：Git + GitHub
- **部署**：Vercel / Netlify / Railway 三选一

### 2.2 适合谁

这套适合：

- 做个人网站
- 做 landing page
- 做简单 Web App
- 做脚本工具
- 做 AI 小产品原型

### 2.3 为什么这套够用

因为它已经能完成一个最基础闭环：

**提需求 → AI 写代码 → 本地运行 → 修改 → 提交 Git → 部署上线**

这就是最重要的起点。

## 3. 工具分类总览

### 3.1 AI 编码助手

#### 用途
负责：

- 根据自然语言生成代码
- 改代码
- 重构
- 查 bug
- 补测试
- 解释项目结构
- 做多文件修改

#### 是否必需
- **必需**

#### 推荐工具
- **Claude Code**
- **Cursor**
- **GitHub Copilot**
- **Windsurf**
- **Aider**
- **Continue**

#### 怎么选
- **Claude Code**：适合终端工作流、仓库级修改、agent 式协作
- **Cursor**：适合 IDE 内直接用 AI 编码
- **Copilot**：适合补全和日常编码
- **Aider**：适合命令行改仓库
- **Continue**：适合自定义模型/本地模型集成

#### 注意事项
- 不要一开始同时订阅 3 个同类工具
- 选一个主力先用熟
- 真正重要的不是“会不会补全”，而是：
  - 能不能读项目上下文
  - 能不能改多个文件
  - 能不能配合测试和终端一起工作

### 3.2 编辑器 / IDE

#### 用途
负责：

- 写代码
- 跳转定义
- 调试
- 插件集成
- 与 AI 助手协作

#### 是否必需
- **必需**

#### 推荐工具
- **VS Code**
- **Cursor**
- **JetBrains 系列**（IntelliJ IDEA / WebStorm / PyCharm）
- **Zed**

#### 推荐建议
- 新手最稳：**VS Code**
- 想更 AI-native：**Cursor**
- 做大型工程、强依赖重构与调试：**JetBrains**

#### 注意事项
- 一个主力编辑器就够了
- 插件别一上来装几十个
- 先保证能写、能跑、能调试

### 3.3 终端 / CLI 工具

#### 用途
负责：

- 跑项目
- 跑测试
- 看日志
- 执行脚本
- 调用 AI agent
- Git 操作
- 部署命令

#### 是否必需
- **基本必需**

#### 推荐工具
- 终端：
  - **iTerm2**
  - **Warp**
  - **Ghostty**
  - **WezTerm**
- Shell：
  - **zsh**
  - **fish**
- 常用 CLI：
  - **gh**（GitHub CLI）
  - **jq**
  - **ripgrep**
  - **fzf**
  - **fd**
- 任务工具：
  - **make**
  - **just**
  - npm scripts / pnpm scripts

#### 推荐建议
最实用组合之一：

- iTerm2
- zsh
- gh
- ripgrep
- fzf

#### 注意事项
- vibecoding 到后面几乎一定会进入终端工作流
- 尤其是：
  - 批量改代码
  - 跑测试
  - 查日志
  - 自动修复
- 但不要沉迷终端美化，先保证命令能跑通

### 3.4 模型 / API 提供商

#### 用途
负责给 AI 助手、自动化 agent、生成代码/文档/测试提供底层能力。

#### 是否必需
- **必需**

#### 推荐选择
- **Anthropic Claude**
- **OpenAI**
- **Google Gemini**
- **OpenRouter**
- 本地模型：
  - **Ollama**

#### 怎么选
看这些维度：

- 代码能力
- 长上下文能力
- 工具调用能力
- 价格
- 延迟
- 稳定性
- 配额/限流

#### 推荐建议
- 主力模型选一个
- 备用模型选一个
- 批处理或低成本任务再考虑便宜模型

#### 注意事项
- 很多时候不是“最聪明”最重要，而是“最稳、最顺手”
- 企业/团队要注意：
  - 数据保留策略
  - 隐私
  - 合规

### 3.5 MCP / 工具集成层

#### 用途
让 AI 不只是“会写代码”，还能：

- 读 GitHub
- 查文档
- 调数据库
- 控制浏览器
- 接设计稿
- 调内部工具

#### 是否必需
- **中后期非常重要**
- 新手可以后加，但很值得学

#### 推荐集成方向
- GitHub
- 文件系统
- Shell
- 浏览���自动化
- 数据库
- 文档知识库
- 设计系统 / Figma

#### 注意事项
- MCP 能显著提升 AI 实战能力
- 但也带来风险：
  - 权限过大
  - 凭证管理混乱
  - 误操作
  - 缺少审计

#### 推荐建议
新手先接这几个就够：
- GitHub
- Shell
- Browser
- Docs

### 3.6 设计 / 原型工具

#### 用途
负责：

- 画界面
- 做原型
- 沟通交互
- 对齐视觉
- 生成前端参考

#### 是否必需
- 做 Web / App：**很常用**
- 做脚本 / 后端：**可选**

#### 推荐工具
- **Figma**
- **Framer**
- **v0**
- **Bolt**
- **Lovable**
- **Storybook**

#### 推荐建议
- 只做产品原型：Figma + v0 / Bolt 很高效
- 做长期可维护前端：要加组件库和 Storybook 思路

#### 注意事项
- AI 生成 UI 很快
- 但不代表结构合理、可维护
- 真正上线前通常还要人工整理：
  - 组件结构
  - 交互细节
  - 响应式
  - 可访问性

### 3.7 后端 / 数据库 / 部署

#### 用途
负责：

- 登录
- 数据存储
- 文件存储
- 服务端逻辑
- 发布上线
- 线上运行

#### 是否必需
- 对大多数产品：**必需**
- 对纯本地脚本：**可简化**

#### 推荐工具

##### 数据库 / 后端
- **Supabase**
- **Firebase**
- **Neon**
- **PlanetScale**
- **Prisma**

##### 部署
- **Vercel**
- **Netlify**
- **Railway**
- **Render**
- **Cloudflare**
- **Docker**

#### 推荐建议
如果你想省心，最常见组合是：

- **前端部署：Vercel**
- **数据库：Supabase / Neon**
- **ORM：Prisma**

#### 注意事项
AI 可以帮你很快搭起来，但不代表这些自动做好了：

- 权限控制
- 数据迁移
- 备份
- 安全策略
- 监控
- 环境变量管理

### 3.8 测试 / 调试 / 质量保障

#### 用途
负责验证 AI 写出来的代码到底是不是“真的能用”。

#### 是否必需
- **必需**

#### 推荐工具

##### 前端 / Web
- **Playwright**
- **Cypress**
- **Vitest**
- **Jest**
- **Testing Library**

##### Python
- **Pytest**

##### 通用质量工具
- **ESLint**
- **Prettier**
- **TypeScript**
- **Chrome DevTools**
- **Sentry**

#### 推荐建议
最值得优先补齐的是：

1. lint
2. type check
3. unit test
4. E2E smoke test

#### 注意事项
vibecoding 最容易出现的问题是：

- 看起来能跑
- 实际一堆边界条件没处理
- 改一处坏三处

所以测试不是后补项，而是**尽早接入**。

### 3.9 自动化 / Agent ��排

#### 用途
负责把开发流程自动化，例如：

- 自动跑测试
- 自动生成 PR
- 自动部署
- 自动同步文档
- 自动处理重复任务

#### 是否必需
- 小项目：可选
- 长期项目：很重要

#### 推荐工具
- **GitHub Actions**
- **n8n**
- **Zapier**
- **Make**
- 自定义脚本
- make / just / npm scripts

#### 注意事项
自动化越强，越要加边界：

- 分支保护
- 人工审核
- 测试门禁
- 生产环境隔离

#### 推荐建议
新手第一步不是上复杂自动化平台，而是先把这些写好：

- `dev`
- `build`
- `test`
- `lint`
- `deploy`

### 3.10 协作 / 知识管理工具

#### 用途
负责：

- 管理需求
- 记录上下文
- 团队沟通
- 给 AI 提供稳定资料

#### 是否必需
- 个人项目：可选
- 团队项目：常常必需

#### 推荐工具
- **Notion**
- **Linear**
- **Jira**
- **Slack**
- **Discord**
- **Obsidian**

#### 注意事项
AI 编程的常见瓶颈不是“代码写不出来”，而是：

- 需求散
- 规范散
- 决策散
- 上下文散

如果要长期用 AI，最好把这些沉淀下来：

- 产品需求
- 技术约束
- 代码规范

### 4.2 做 AI Web App

#### 最小配置
- 编辑器：VS Code / Cursor
- AI：Claude Code / Cursor
- 前端：Next.js
- 后端：Serverless / API Routes
- 数据库：Supabase
- 部署：Vercel

- Prisma

- 自建 Kubernetes
- 太早做性能工程化

**先把“用户输入 → AI 处理 → 输出结果”链路打通。**

- 编辑器：VS Code

- Pytest / Vitest
- 日志系统
- 定时任务
- Docker

#### 不建议一开始就加
- 复杂前端
- 过早��云
- 一堆 workflow 平台

#### 一句话建议
**脚本类项目先在本地跑通，再考虑服务化。**

### 4.4 做带数据库的 CRUD 产品

#### 最小配置
- 编辑器：VS Code / Cursor

- 数据库：Supabase / Neon / PlanetScale
- 部署：Vercel / Railway / Render

#### 可选增强
- Prisma
- Auth
- Admin 面板
- Playwright
- Sentry

#### 不建议一开始就加
- 多数据库混用
- 自己造后台系统
- 过度拆服务

#### 一句话建议
**选一个“默认就能做 CRUD”的成熟方案，比拼装强。**

## 5. 预算分层建议

### 5.1 零预算版

适合：

- 学习
- 做 demo
- 尝试 vibe coding

组合思路：

- VS Code
- 免费 AI 配额 / 试用
- 免费部署
- 免费数据库额度

注意：
- 配额容易不够
- 性能和稳定性有限

### 5.2 低预算版

适合：

- 认真做个人项目
- 想提高效率
- 可以每月小额投入

建议把钱优先花在：

1. **主力 AI 工具**
2. **部署稳定性**
3. **必要的数据库资源**

不要一开始同时订阅多个 AI。

### 5.3 中预算版

适合：

- 长期维护项目
- 有用户
- 开始重视稳定性和效率

建议投入：

- 主力 AI
- 稳定数据库
- 日志监控
- 测试与自动化
- 团队协作工具

## 6. 从零搭建的推荐顺序

按这个顺序来最不容易乱：

### 第一步：先定目标
先回答：

- 我要做网页、脚本、App 还是 AI 产品？
- 要不要上线？
- 要不要登录？
- 要不要数据库？
- 要不要多人协作？

### 第二步：选主栈
只决定这几个：

- 一个编辑器
- 一个 AI 工具
- 一个语言 / 框架
- 一个部署平台

### 第三步：做本地 demo
先做到：

- 能运行
- 能改一点功能
- 能让 AI 帮你修改
- 不报一堆基础错误

### 第四步：加 Git 和部署
做到：

- 提交代码
- 推到 GitHub
- 成功上线一次

### 第五步：再加数据库 / 登录 / 测试
只有真的需要时再加。

### 第六步：最后才加自动化 / 监控 / 高级集成
这是升级项，不是起步项。

## 7. 常见坑

### 7.1 一开始装太多
表现：

- 编辑器试了 3 个
- AI 工具买了 4 个
- 部署平台收藏了 6 个
- 结果一个 demo 都没跑通

### 7.2 没有主栈
表现：

- 什么都懂一点
- 但没有一套自己能稳定输出的组合

### 7.3 过早追求高级工程化
表现：

- 还没做出 MVP
- 就开始折腾 CI/CD、容器化、监控全家桶

### 7.4 把 AI 当自动完成器
表现：

- 只会一句话丢需求
- 不会拆任务
- 不会验证结果
- 不会追踪 bug

### 7.5 忽略测试与部署
表现：

- 本地好像行
- 一上线全坏
- 环境变量全乱
