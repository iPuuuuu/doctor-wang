# UI-001: Android 核心产品体验与设计系统重构

## Goal
在不改变后端契约与医疗安全边界的前提下，将现有 Compose 客户端从功能型 Demo 提升为具备一致视觉层级、完整状态反馈和移动端可用性的健康辅助产品。

## Scope / Architecture Decision
- 复用现有 Kotlin + Jetpack Compose + Material 3，不迁移框架、不引入额外 UI 库。
- 通过共享 design tokens、页面容器、状态组件和结构化消息渲染渐进改造，不重写导航/Repository 数据流。
- 保留 Android → Spring Boot → AI Service 边界；不新增或修改后端 API。
- 不伪造后端未支持的 stop generation、新会话、服务端 regenerate 等能力。

## Alternatives Considered
1. 引入第三方 Compose design system / markdown 库：实现快，但增加依赖、主题割裂和供应链成本，本轮不采用。
2. 重写为全新导航壳与底部导航：范围和回归风险过大，本轮不采用。
3. 现有 Material 3 上渐进统一（采用）：收益高、契约零变更、可分片回滚。

## Output
- 统一 Typography、Shapes、页面间距、卡片和 loading/error/empty 状态。
- 修复核心页面显式返回导航、档案编辑入口、报告咨询入口和空态 CTA。
- 改善 AI 对话快捷问题、失败重试、结构化 Markdown、引用与思考状态。
- 改善报告列表/详情、上传、健康档案在 375–430dp 宽度下的信息层级。
- 补充纯逻辑单元测试与构建/静态验证证据。

## Acceptance Criteria
- [x] 首页服务入口无三列拥挤，静态 375dp 约束审查通过；真机视觉待补。
- [x] Chat / Upload / Profile / Report Detail / Settings 均有显式返回路径。
- [x] 健康档案可进入编辑；空病史/空检查记录有明确空态。
- [x] 报告列表空态可上传；详情状态中文化，主要/次要/危险操作分层。
- [x] AI 推荐问题可点击；发送失败可重试；常见 Markdown 结构可读；引用和安全提醒清晰。
- [x] 医疗边界声明保持可见，未知/失败状态不显示为成功。
- [x] Android 22/22 unit tests、lintDebug、assembleDebug、git diff --check 通过；真机检查明确 NOT RUN。
